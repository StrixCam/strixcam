# feat: Retarget firmware cross-build to JetPack 7.2 (L4T r39.2 / Ubuntu 24.04)

## Summary

Retarget the firmware cross-build from JetPack 6.2.2 (L4T r36.5 / Ubuntu 22.04, NVIDIA crosscompile container + Bootlin GCC 11) to JetPack 7.2 (L4T r39.2 / Ubuntu 24.04). NVIDIA has **not** published a 7.x `jetpack-linux-aarch64-crosscompile-x86` container, so the sysroot moves to the **publicly-downloaded L4T r39.2 BSP sample rootfs** (the tegra-correct source that ships OpenCV, the NVMM/`nvarguscamerasrc`/`nvvidconv` GStreamer stack, and the Jetson CUDA path), cross-built with the Ubuntu `gcc-13-aarch64-linux-gnu` toolchain. arm64 unit tests continue to run under qemu-user in CI (an existing capability, retained). Work continues on `release/0.1.0`; the first prerelease after retarget is `v0.1.0-beta.2`, then stable `0.1.0` as the first complete release.

---

## Problem Frame

Firmware compiles cleanly for JetPack 6.2.2 but the project is moving its only supported platform to JetPack 7.2 before shipping any stable release. The 6.2 cross-build leans entirely on the `nvcr.io/nvidia/jetpack-linux-aarch64-crosscompile-x86:6.1` container, which provides both the Bootlin toolchain and the **targetfs sysroot** (Tegra-built OpenCV, NVMM GStreamer plugins, tegra libs). For 7.2 that container does not exist (latest published tag is `:6.1`), so a straight base-image bump is impossible. The replacement is **not** a generic Ubuntu rootfs — that would drop the Jetson-specific libraries the firmware links — but NVIDIA's L4T r39.2 BSP sample rootfs, which is the public, tegra-correct equivalent of what the container's targetfs provided.

- R2. JetPack 6.2 / r36.5 / jammy / Bootlin-2022.08 support is removed entirely — no dual-target (origin decision; fallback risk accepted).

## Scope Boundaries

- No dual 6.2 + 7.2 support — 6.2 is removed (no-fallback risk explicitly accepted; mitigated only by git history + the `v0.1.0-beta.1` tag).
- **Definition of done = a Jetson-runnable arm64 binary produced from BOTH paths:** (1) locally via the dev container, and (2) remotely via CI/CD (the beta release artifact). "Runnable on Jetson" is what makes the BSP-rootfs (tegra-correct sysroot) and the qemu ctest gate load-bearing — a binary that merely compiles is not done. Keep iterating until both paths emit a binary that links the correct r39.2/tegra libs and passes qemu execution.
- On-device execution on real Jetson hardware is still **deferred** (user is validating later); the qemu-user run + correct tegra BSP sysroot stand in as the runnable-confidence proxy until then. Hardware bring-up is a separate milestone.
- No proto/app/emulator repo changes beyond verifying the contract builds against protobuf 3.21 (R4).
- No CI ladder redesign — existing alpha/beta/stable flow and `resolve-version.sh` reused as-is.
- No new firmware features; **no Jetson CUDA/TensorRT linkage in this work** (intelligence stays deferred per the hardware-demo plan).

### Deferred to Follow-Up Work

- **Jetson (tegra) CUDA/TensorRT cross-link**: deferred to the intelligence un-defer milestone, where the *tegra* CUDA flavor (not SBSA) is sourced from the L4T BSP / `cuda-tegra` apt and validated against real TensorRT needs. (The earlier SBSA-CUDA overlay was cut — wrong GPU variant for the Orin iGPU, and nothing links it now.)
- **Hardware-bound tests** (IMX477 capture, NVENC, BlueZ): remain device-only, excluded from the qemu gate (unchanged from 6.2).
- **Wire CI to pull the GHCR-published devcontainer** instead of per-run rebuild: stays measurement-gated; the new BSP-rootfs sysroot changes the disk/time math, so re-measure when un-deferring.
- **Promote FindProtobuf + conan-cache + BSP-rootfs build recipe into `docs/solutions/`** via `/ce-compound` after the retarget lands.

## Key Technical Decisions

- **Sysroot = L4T r39.2 BSP sample rootfs, not a generic noble rootfs and not SBSA.** This is the tegra-correct equivalent of the old container targetfs: it carries OpenCV 4.8 (`.so.408`), the NVMM/`nvarguscamerasrc`/`nvvidconv` GStreamer stack the runtime pipeline needs, and the Jetson CUDA path. Generic noble would silently drop all of these (build fails on OpenCV; runtime pipeline fails on device). SBSA is the Grace/datacenter ARM variant — wrong runtime family for the Orin iGPU.
- **Drop the CUDA cross-package overlay from this plan.** Current firmware links no CUDA/TensorRT; R1 does not depend on it. When intelligence un-defers, the *tegra* CUDA flavor (from the BSP) is the correct one — installing SBSA CUDA now would be the wrong variant and add CI-disk pressure for zero present value.
- **Toolchain: Ubuntu `gcc-13-aarch64-linux-gnu` (GCC 13 / glibc 2.39), triple `aarch64-linux-gnu`.** Replaces Bootlin `aarch64-buildroot-linux-gnu` GCC 11 / glibc 2.35 (ABI-incompatible with the r39.2/noble rootfs). The single triple collapses the buildroot↔linux-gnu symlink bridge in `002_fix_sysroot.sh`. (Confirm against NVIDIA's documented r39.2 cross toolchain — Deferred.)
- **Retain qemu-user arm64 ctest — it is an existing capability, not future work.** Keep `CMAKE_CROSSCOMPILING_EMULATOR` in the new toolchain file and install `qemu-user-static` in the new base image (the old NVIDIA container supplied qemu; `ubuntu:24.04` does not). R1's gate is "ctest green under qemu," so a glibc/ABI mismatch in the new sysroot is caught at build time, not on device.
- **Stay on `release/0.1.0`; cut `v0.1.0-beta.2`.** No stable shipped, so `0.1.0`'s meaning isn't frozen; `beta.2` sorts after `beta.1` (no resolver brick). Because `beta.1` (6.2/glibc 2.35) and `beta.2` (7.2/glibc 2.39) are **not substitutable**, add a `platform:` marker to release bodies and an `install.sh` guard that refuses to install across the platform boundary within the line.
- **`arch=armv8` stays; bump `compiler.version` 11→13.** Only the compiler version and triple change in the conan profiles.

## Open Questions

### Resolved During Planning

- L4T version for JetPack 7.2 → **r39.2** (not r38). Orin Nano supported on 7.2 (not 7.0/7.1).
- How to source the sysroot without an NVIDIA 7.x container → **L4T r39.2 BSP sample rootfs** (tegra-correct; resolves OpenCV + NVMM GStreamer + future CUDA).
- Is arm64 test execution new work → **no, it already runs under qemu** in CI; retained, not deferred.
- Versioning/branch → stay `release/0.1.0`, `v0.1.0-beta.2`; 6.2 deleted (fallback risk accepted).

### Deferred to Implementation

- **Exact L4T r39.2 BSP + sample-rootfs download artifacts** (driver package + `tegra_rootfs`/sample rootfs tarball names, sizes, and whether NVIDIA publishes the Orin-family rootfs for r39.2 in cross-friendly form). Confirm from the JetPack 7.2 archive at execution.
- **NVIDIA's documented r39.2 cross toolchain** — whether Ubuntu `gcc-13-aarch64-linux-gnu` is the blessed compiler or NVIDIA recommends a specific gcc/Linaro build for r39.2; verify before locking U3/U4.
- **Whether the BSP sample rootfs ships OpenCV `-dev` headers** or runtime `.so` only. If runtime-only, U5 must add `libopencv-dev` arm64 (matched to the BSP's `.so.408`, not noble's `.so.406`) — make this an explicit U3→U5 gate.
- **Whether noble's host `protobuf-compiler` is exactly 3.21.12** — pin if it diverges from the sysroot libprotobuf.
- **Whether noble ships a protobuf CMake CONFIG package** (jammy did not, forcing MODULE mode) — re-confirm against real `find_package` behavior; keep MODULE override if still needed.

```
CROSS_SYSROOT ─► BSP rootfs path   |   host protoc 3.21.12 ⇄ target libprotobuf 3.21.12 (match + regenerate .pb.*)
```

## System-Wide Impact

- **Interaction graph:** sysroot scripts `001`/`002`/`003` are order-coupled; toolchain file, conan profiles, `CMakePresets.json`, and `scripts/tidy-args.sh` all reference the sysroot path + triple — change one without the others and configure breaks. `CMAKE_CROSSCOMPILING_EMULATOR` couples the build to `qemu-user-static` in the base image.
- **Error propagation:** a missing BSP lib (OpenCV/NVMM), a noble-package 404 (U5), or a protoc/lib mismatch (U6) surfaces as a link/static-assert error far from cause — fail loudly at fetch/configure/codegen time.
- **State lifecycle risks:** stale `.cache/sysroot/jetson-r36.5` and old conan cache must not shadow the new sysroot; cache keys change with the new profile.
- **API surface parity:** none — wire/RPC contract unchanged; only the build platform changes. proto/app/emulator untouched beyond the R4 contract-build check.
- **Integration coverage:** the meaningful proof is cross-link + **ctest green under qemu** (U4/U6) and CI green (U7); on-device hardware tests stay deferred.
- **Unchanged invariants:** `resolve-version.sh`, the alpha/beta/stable ladder + required-check job names, the no-build stable promotion with SHA-256 verify, and `conanfile.py` deps (still no CUDA) all stay as-is.
