# JetPack 7.2 Cross-Build Retarget — Requirements

**Date:** 2026-06-22
**Repo:** sst-cam-firmware
**Status:** Ready for planning
**Scope:** Standard (bounded infra retarget)

## Problem

Firmware cross-build is pinned to JetPack 6.2.2 (L4T r36.5, Ubuntu 22.04 jammy). The code compiles for 6.2, but the project is moving its supported platform to the latest **JetPack 7.2** (L4T r39.2, Ubuntu 24.04 noble) before shipping a stable release. The cross-compile toolchain, sysroot, and container must be retargeted, and the in-flight `0.1.0` release line must absorb the platform change cleanly.

## Decision: versioning & branch

- **Stay on `release/0.1.0`.** No stable release has ever shipped, so `0.1.0`'s meaning is not yet frozen — prereleases are explicitly in-flux.
- `0.1.0` becomes the **first complete release**, targeting JetPack 7.2.
- `v0.1.0-beta.1` (which targeted 6.2) is treated as an early prerelease made before the OS target settled. It is **discarded**, not supported.
- Next prerelease = **`v0.1.0-beta.2`** (targets 7.2). Sorts after `beta.1` — no semver-ordering brick. Then stable `0.1.0`.
- Existing alpha/beta/stable CI ladder is reused as-is; no pipeline redesign.

## Goal / value

A firmware that cross-builds cleanly against JetPack 7.2 in the dev container, with 6.2 fully removed and the `0.1.0` release line carrying the new platform target.

## Success criteria

- All CMake presets (`debug`, `release`, `test`) cross-build green in the new 7.2 dev container.
- No remaining references to r36.5 / 6.2 / jammy in toolchain, profiles, presets, sysroot scripts, or docs.
- `v0.1.0-beta.2` cuts successfully through the existing release-alpha/beta CI flow on `release/0.1.0`.
- README.md and CLAUDE.md state JetPack 7.2 / L4T r39.2 / Ubuntu 24.04 as the target.
- Release notes / CHANGELOG carry a one-line note that the platform target moved from JetPack 6.2 to 7.2 between `beta.1` and `beta.2`.

## Scope — files to retarget

Mechanical retarget r36.5 → r39.2, jammy → noble:

- `.devcontainer/Dockerfile` — base image `nvcr.io/nvidia/jetpack-linux-aarch64-crosscompile-x86:6.1@sha256:…` → 7.2 tag + new digest.
- `cmake/toolchains/jetson-r36.5.cmake` → r39.2 toolchain (sysroot path, Bootlin toolchain version, compiler paths).
- `conan/profiles/jetson-r36.5-cross` → r39.2 profile (compiler version if Bootlin changes).
- `CMakePresets.json` — `CONAN_HOST_PROFILE`, `CMAKE_TOOLCHAIN_FILE`, and the hardcoded `/l4t/aarch64--glibc--stable-2022.08-1` toolchain PATH.
- `.devcontainer/sysroot/001_unpack_l4t.sh` — verify r39.2 BSP rootfs layout (split vs single).
- `.devcontainer/sysroot/003_install_extra_pkgs.sh` — **highest-risk:** retarget all Ubuntu jammy pool URLs → noble; reconcile lib versions (GStreamer 1.20→1.24, protobuf must stay synced with host protoc, x264/sdbus-c++/gst-rtsp-server/Cairo/Pango).
- `README.md`, `CLAUDE.md` — platform target strings.
- `.github/workflows/release-alpha.yml` — `:6.1` base-image comment (workflow auto-picks the new image; no version hardcode).

## Risks / unknowns (for planning to resolve)

- **noble package availability/versions** — exact pool URLs and SONAME stability for GStreamer 1.24, protobuf, codecs on Ubuntu 24.04 arm64. The protobuf/host-protoc version sync is the sharpest pin.
- **r39.2 sysroot layout** — whether the 7.2 cross-compile image splits `targetfs.tbz2` like 6.1 did; `001_unpack_l4t.sh` is defensive but unverified against r39.2.
- **Bootlin toolchain version** — whether r39.2 needs a newer glibc/gcc than `2022.08-1` / gcc 11, which would ripple into the conan `compiler.version`.
- **GitHub runner disk** — r39.2 sysroot assembly may exceed the ~37 GB already flagged in `release-alpha.yml`.

## Dependencies / assumptions

- Scope is **firmware repo only**. sst-cam-proto, sst-cam-app, sst-cam-emulator are assumed unaffected by the platform jump (revisit if the protobuf version on noble differs from the pinned contract).
- **On-device runtime validation on real Jetson hardware is NOT part of this work** — "done" = clean cross-build + green CI + updated docs. Hardware bring-up is a separate milestone.
- `v0.1.0-beta.1` has no live consumer to break.

## Out of scope

- Dual 6.2 + 7.2 support.
- On-device / hardware validation.
- proto/app/emulator changes.
- CI/CD ladder redesign.
